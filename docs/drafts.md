# Drafts

`draft` is a field, conceptually included in the base template, with validation on all objects to
ensure that it is a Boolean value.

Drafts only exist when Eleventy runs in `--serve`/`--watch` mode (`npm start`).

## Where drafts appear

Locally, drafts are **not** mixed into any post list.
They are kept out of the blog index, the RSS feed, the home page's latest-posts strip, and the tag pages, so those match what production shows.
They are listed instead on `/drafts/`, generated by `src/content/drafts.njk`.
The page carries `draft: true`
itself, so the same preprocessor drops it from production builds.

The exclusion is done in the preprocessor by setting `eleventyExcludeFromCollections` to the post's own tag list.
The array form (rather than `true`) keeps the item in the `all` collection, which both the nav and the `draft` collection's glob need.

## The `draft` tag and collection

The preprocessor prepends a `draft` tag to draft posts, so the red "Draft" badge renders first in the badge list.
That badge is all the tag is — `src/_includes/partials/tag.njk` points it at `/drafts/` rather than `/tags/draft/`, `src/content/tag-pages.njk` filters `draft` out of the tag pages it generates, and `src/content/tags.njk` skips it in the tag list.

The `draft` collection is built by `eleventyConfig.addCollection("draft", ...)` in `src/_11ty/collections/draft.js` from a glob over `src/content/blog/**/*.md` filtered on `data.draft`, not from the tag — the dynamic tag is added after the automatic collections are ormed, and the tag collection is suppressed by `eleventyExcludeFromCollections` anyway.
